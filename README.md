# Dayly Bot

Бот для сбора ежедневных отчётов (дейликов) в мессенджере **VK Teams** (MyTeam). Каждый рабочий день в 11:15 бот рассылает участникам напоминание рассказать, чем они занимались вчера и что планируют делать сегодня.

## Описание

Бот работает через SDK **vkwrksps-bot** (неофициальный порт оригинального Python SDK на Node.js) и общается с API VK Teams посредством long polling. Он автоматически:

- рассылает напоминания о ежедневном отчёте по будним дням;
- принимает и накапливает ответы участников;
- позволяет посмотреть свой ответ, очистить его или заранее заполнить отчёт на завтра;
- предоставляет модераторам и владельцу инструменты управления участниками и массовой рассылки;
- отдаёт собранные за день отчёты через встроенный HTTP-сервер.

## Как это работает

### Ежедневный опрос (будильник)

В `index.js` определён объект `alarmClock` с временем запуска опроса — по умолчанию `11:15`.

Каждую секунду выполняется `checkAlarmClock()`:

1. Если сегодня выходной (`сб` или `вс`) — опрос пропускается.
2. Если текущее время достигло времени из `alarmClock` и для этого дня опрос ещё не отправлялся — бот рассылает напоминание всем участникам из `chats.log`.
3. Напоминание не отправляется тем, кто уже заполнил отчёт на текущий день.

### Сбор отчётов

Участник отправляет боту любое текстовое сообщение (не команду) — оно автоматически добавляется к его отчёту за текущий день. Текст накапливается: каждое следующее сообщение добавляется к предыдущему с переводом строки (join через `\n`).

Отчёты хранятся в файлах `days/<ключ>.json`, где ключ имеет формат `мес-дд` (например, `авг-12`). Внутри — объект вида:

```json
{
  "chatId@domain": "текст отчёта",
  "another@domain": "текст другого отчёта"
}
```

### Хранение данных

| Файл            | Назначение                                                       |
|-----------------|------------------------------------------------------------------|
| `chats.log`     | Список chatId участников (по одному на строку)                   |
| `mods.log`      | Список chatId модераторов (по одному на строку)                  |
| `days/*.json`   | Отчёты участников по дням                                        |
| `logs/`         | JSON-дампы каждого входящего события (имя: `<timestamp>-<chatId>-<rand>`) |

### Веб-сервер

Вместе с ботом поднимается простой HTTP-сервер (хоcт и порт задаются через `WEB_SERVER_HOST` / `WEB_SERVER_PORT`).

Доступные маршруты:

- `GET /report` — возвращает JSON с общим количеством участников и отчётами за день:
  ```json
  {
    "total": 5,
    "data": { "chatId@domain": "текст отчёта" }
  }
  ```
- всё остальное — `{"debug": "=)"}`

Сервер поддерживает CORS (отражает заголовок `Origin`).

## Команды бота

### Команды для всех участников

| Команда          | Описание                                                        |
|------------------|-----------------------------------------------------------------|
| `/start`         | Зарегистрироваться как участник; владелец получает уведомление  |
| `/help`          | Показать справку по командам                                     |
| `/stop`          | Выйти из рассылки (удаляет chatId из `chats.log`)               |
| `/view`          | Показать свой отчёт за текущий день                             |
| `/view tomorrow` | Показать отчёт, заполненный на завтра                           |
| `/reset`         | Очистить свой отчёт за текущий день                             |
| `/reset tomorrow`| Очистить отчёт на завтра                                        |
| `/tomorrow <текст>` | Заранее заполнить отчёт на завтра                            |

### Команды для модераторов / владельца

Доступны, если chatId совпадает с `MASTER_CHAT_ID` или входит в `mods.log`:

| Команда            | Описание                                                        |
|--------------------|-----------------------------------------------------------------|
| `/members`         | Показать список всех участников                                 |
| `/kick <chatId>`   | Удалить участника из рассылки                                   |
| `/mod <chatId>`    | Добавить модератора                                             |
| `/unmod <chatId>`  | Удалить модератора                                              |
| `/mods`            | Показать список модераторов                                     |
| `/list`            | Показать список участников, заполнивших отчёт                   |
| `/spam <текст>`    | Массовая рассылка всем участникам (с сохранением форматирования)|
| `/report`          | Показать сводный отчёт: кто что написал за сегодня              |

Примечание: `/spam` сохраняет форматирование исходного сообщения (жирный, курсив, ссылки, код). Форматирование сообщения сдвигается относительно текста рассылки, чтобы корректно наложиться на отправляемый контекст.

## Переменные окружения

Все переменные задаются в файле `.env` (см. `.env.example`):

| Переменная          | Описание                                             |
|---------------------|------------------------------------------------------|
| `VKTEAMS_TOKEN`     | Токен бота VK Teams                                  |
| `VKTEAMS_API_URL`   | URL API VK Teams (по умолчанию `https://api.internal.myteam.mail.ru/bot/v1/`) |
| `MASTER_CHAT_ID`    | chatId владельца бота (получает служебные уведомления)|
| `JIRA_URL`          | Базовый URL Jira (для модуля `jira.js`)              |
| `JIRA_TOKEN`        | Bearer-токен доступа к Jira API (для модуля `jira.js`)|
| `WEB_SERVER_PORT`   | Порт HTTP-сервера (по умолчанию `7070`)              |
| `WEB_SERVER_HOST`   | Хост HTTP-сервера (по умолчанию `localhost`)         |

## Модули приложения

### index.js

Главный модуль. Выполняет:

- подключение к VK Teams через `new Bot({ token, apiUrl })`;
- обработку входящих сообщений и маршрутизацию команд;
- ежедневный опрос (`alarmClock`, `checkAlarmClock`);
- управление участниками (`chats.log`) и модераторами (`mods.log`);
- работу с отчётами (`days/*.json`): чтение, добавление, очистка, просмотр;
- массовую рассылку `/spam` со смещением форматирования;
- встроенный HTTP-сервер для отдачи `/report`;
- глобальную обработку `unhandledRejection` и `uncaughtException`, чтобы процесс не падал.

### utils.js

Вспомогательные функции:

- `getDate()` / `getTime()` / `getTomorrow()` / `isDayOff()` — работа с датами: ключ дня (`авг-12`), день недели, время `HH:MM`, проверка выходных;
- `getSlavicName(chatId)` — преобразование chatId в «славянское» имя: берёт имя до `@`, транслитерирует латиницу в кириллицу и приводит к виду «Имя»;
- `formatNum()` / `formatDuration()` — склонение числительных и форматирование длительности (недели/дни/часы);
- `shiftFormat()` / `formattedMessage()` / `contextMessage()` — работа с форматированием сообщений VK Teams;
- `extractNumbers()` / `uniq()` — извлечение чисел из текста и уникализация массива.

### jira.js

Модуль интеграции с Jira. Экспортирует `getIssueData(issueKey)` — получает данные о задаче по ключу (например, `VKPL-123`) через REST API Jira:

- делает `GET {JIRA_URL}/rest/api/2/issue/{issueKey}` с Bearer-токеном;
- сохраняет сырой ответ в `tmp/<issueKey>.json`;
- возвращает `{ issueKey, status, summary, performer, sprint }`.

> **Внимание:** в текущей версии `index.js` вызовы Jira закомментированы — модуль зарезервирован для будущего функционала (подстановка информации о задачах в отчёты `/report`). Функция `replaceMentionedTasks()` в `index.js` содержит логику замены упомянутых тасков на данные из Jira.
